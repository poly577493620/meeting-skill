### C 安全合规与脱敏（主要问题）

1. **区间规范与脚本判断口径不一致（误报风险）**
   - `redaction-rules.md` 原文允许"半整数级别"区间边界，可能产生 `2.5亿—3.5亿` 这类含小数的边界区间；

     会把合规的小数边界区间误判为"精确金额泄漏"。
   - 题目明确要求："合理的金额区间不应被错误识别为精确金额泄漏。" 属于脚本误报问题。

2. **脚本对禁用占位词无检查**
   - `output-schema.md` 规定缺失字段只允许写"未明确"，禁用"待定/TBD/暂无/待补充"等；
   - 原脚本只检查空单元格，未检查这些禁用占位词。

3. **脚本错误信息口径不够收敛**
   - 原脚本部分提示文案以 `[...]` 方括号包裹占位词，与规范文案用词不统一；

## 三、Claude Code 实际修改内容

### 1. `references/redaction-rules.md`（脱敏规则）

- 将"区间宽度通常取整数级别或半整数级别"改为"区间边界一律取整数级别（如 2亿、4000万），不使用小数边界"，消除与脚本判断的口径冲突；
- 补充单位一致性要求（统一写 `2亿—3亿元` 而非 `2亿—3亿`）；
- 在"注意事项"补充脚本行为说明：完整区间 `X—Y亿/万` 形式不会被脚本误报，含小数的独立金额会被提示人工复核。

### 2. `scripts/check_minutes.py`（结构校验脚本）

- **新增禁用占位词检查**：`FORBIDDEN_PLACEHOLDERS = ['待定','tbd','暂无','不适用','待补充','待确认']`，对行动项单元格检查，命中时只输出行列与占位词大类，不回显具体内容；
- **新增区间豁免逻辑**：`RANGE_AMOUNT_PATTERN` 识别 `X—Y亿/万` 形式（含整数与小数边界区间），区间内的小数金额不再被误报为精确金额泄漏；分隔符兼容中文破折号(U+2014)、全角/半角连字符、波浪号及汉字"至/到"；
- **修正金额告警文案**：由"含小数的 X.X亿/X.X万"改为"未呈现为完整区间的带小数金额"，避免在提示中暗示原始数值；
- **统一错误信息口径**： prohibits 占位词提示用引号包裹"未明确"，不回显敏感原文；脱敏说明缺失项检查信息只指明类别，不输出文件内容；
- 全程仅使用 Python 标准库（`sys`、`os`、`re`），未引入第三方依赖。
