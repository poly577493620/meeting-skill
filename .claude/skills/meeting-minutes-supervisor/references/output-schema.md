# 会议纪要输出结构定义

本文件只负责定义最终输出的 Markdown 结构，不包含角色说明或完整工作流程。

## 固定输出结构

```markdown
# 结构化会议纪要

## 会议基本信息

- 会议主题：
- 会议时间：
- 参会人员：

## 会议讨论

### 议题一

- 核心内容：
- 相关观点：
- 待确认内容：

## 明确决议

1. 未形成明确决议。

## 行动项

| 编号 | 行动事项 | 责任人 | 协同方 | 截止时间 | 交付物/验收点 |
|---|---|---|---|---|---|

## 未明确事项

1. 未明确。

## 脱敏说明

- 客户姓名：
- 敏感金额：
- 秘密项目代号：
```

## 填写规则

### 会议基本信息

- **会议主题**：从转写内容中提取。如无法识别，写"未明确"。
- **会议时间**：保留原始日期信息。如转写中未提及，写"未明确"。
- **参会人员**：列出转写中出现的参会人员。内部员工姓名保留；客户自然人姓名替换为 `[客户姓名已脱敏]`。

### 会议讨论

- 按议题分组，每个议题包含"核心内容""相关观点""待确认内容"三项。
- **核心内容**：该议题讨论的主要事项。
- **相关观点**：参会人员表达的观点，保留原意，删除口语化表达。不同人员观点冲突时分别记录，不自行裁决。
- **待确认内容**：讨论中提及但尚未确认的事项。
- 不添加因果推断或转写中没有的信息。
- 议题名称从转写内容中归纳，不自行编造。

### 明确决议

- 只记录会议中明确确认的决议。
- **决议认定标准**：必须存在明确的同意、确认、批准或决定性表述（如"同意""通过""确认""决定""批准"等）。
- "建议""可以考虑""应该""需要研究"等表述不构成决议。
- **没有明确决议时写"未形成明确决议"。**

### 行动项

- 每个行动项必须包含 6 个字段：编号、行动事项、责任人、协同方、截止时间、交付物/验收点。
- 编号从 1 开始递增。
- **缺失字段统一写"未明确"。**
- **不得用空白、破折号或推测内容代替"未明确"。**
- 不得根据上下文推测任何字段的值。
- **日期换算**：
  - 会议日期明确时，可将相对日期（如"本周五""下周一"）换算为绝对日期。
  - 无法可靠换算时，保留原始相对日期，并标注"绝对日期未明确"。
  - 不得在会议日期不明确时强行换算。
- 如无行动项，写"本次会议未明确行动项"。

#### 行动项拆分原则

一句话或一段指令中包含多个可独立执行的事项时，必须按下列原则拆分，以避免截止时间或交付物被错误合并或扩展：

1. **逐项独立判断**：分别判断每个事项的责任人、协同方、截止时间和交付物，不以其中一项的属性默认套用到其它事项。
2. **不同时限必须拆分**：当多个事项的截止时间不同，或只有其中一项有明确截止时间时，必须拆分为多条行动项。不得把仅有部分事项享有的截止时间扩展到同一句中的其它事项。
3. **时间表达不得扩展**：时间表达只能应用于原文明确限定的事项。同一句话中出现的截止时间，若原文未明确限定到其它事项，不得自动扩展。
4. **"安排"不等于"完成"**：对"安排会议""组织会议""发起宣贯"等安排类表述，只能记录为"安排/组织"动作本身，不得自行改写为"完成"，也不得为该安排动作补写原文未明确给出的完成期限。
5. **按事项层级拆分**：若同一目标下存在"解决某项问题"与"提交某份证明该问题已解决的报告"两个层级的事项，应分别判断。报告类事项以原文明确给出的截止时间和交付物为准；问题解决类事项若原文未明确给出精确截止时间，必须写"未明确"，不得借用报告事项的截止时间。
6. **无明确截止时间写"未明确"**：某项任务没有明确截止时间时，必须写"未明确"，不得借用相关事项的截止时间或自行设定。
7. **无明确交付物写"未明确"**：某项任务没有明确交付物或验收点时，必须写"未明确"，不得借用相关事项的交付物。
8. **不得为减少行数而合并**：不得为了减少表格行数而合并具有不同截止时间或交付物的任务。

#### 行动项表格格式（固定）

| 编号 | 行动事项 | 责任人 | 协同方 | 截止时间 | 交付物/验收点 |
|---|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |

### 未明确事项

- 列出转写中提及但缺少明确信息的关键事项。
- 例如：提及了某任务但未指定责任人、提及了某交付物但未指定截止时间等。
- 不得将推测或编造的内容列入此部分。
- 如无未明确事项，写"无"。

### 脱敏说明

- **客户姓名**：填写脱敏处理情况。如涉及客户姓名，写"已替换为 [客户姓名已脱敏]"；如未涉及，写"本次纪要不涉及客户姓名"。
- **敏感金额**：填写脱敏处理情况。如涉及精确金额，写"已转换为合理区间"；如未涉及，写"本次纪要不涉及精确金额"。
- **秘密项目代号**：填写脱敏处理情况。如涉及项目代号，写"已替换为 ******"；如未涉及，写"本次纪要不涉及秘密项目代号"。
- **不得在脱敏说明中泄露任何原始敏感值。**

## 输出约束

1. 纪要必须严格按上述六部分顺序输出，不得增减部分或调整顺序。
2. **会议讨论、明确决议和行动项必须分开**，不得将讨论内容混入决议，也不得将决议混入行动项。
3. 所有缺失字段统一写"未明确"，不得使用空白、破折号、"待定""TBD""暂无"等其他表述。
4. 行动项表格必须使用标准 Markdown 表格语法，不得使用列表或其他格式替代。
5. 纪要中不得包含自检过程、思维过程或中间草稿。
